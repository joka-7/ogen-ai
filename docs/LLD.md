# Low-Level Design

Per-file, per-function detail: what each piece of `ogen-ai` actually does, its exact inputs
and outputs, and the file-format contracts that `tests/` enforces. Read `docs/HLD.md` first
for the system-level shape this fits into; read `docs/DESIGN.md` for the *why* behind any
decision recorded here. Line numbers below are as of this writing and drift — the function
names and file paths are the stable reference.

## 1. `bin/ai-sync` — the generator

Single file, stdlib-only (`argparse`, `os`, `re`, `shutil`, `sys`, `pathlib`, `tomllib`).
Entry point `main()` does exactly five things, in order, then returns 0:

```
main()
 1. parse --project / --dry-run / --force / --local-only
 2. m = load_manifest(project_root)                    # read ai-config.toml
 3. agents_content = build_agents_md(...)               # assemble
    write_file(project_root / "AGENTS.md", ...)         # the one real generated file
    check_token_budget(agents_content, m, rep)           # warn only, never fails
 4. wire_tools(submodule, project_root, m, agents_path, rep, force)
 5. if local_only: apply_local_only(project_root, m, rep)
 6. print "done." / "dry-run complete"
```

`submodule = Path(__file__).resolve().parent.parent` (not derived from `project_root`) is
what lets one clone of this repo run against any project via `--project` alone — no `.ai/`
vendored inside the target. See §1's local-only note below and DESIGN.md §14.

### Core data structures

- **`m: dict`** — the parsed `ai-config.toml`, shape:
  ```toml
  [stack]
  languages = ["python", "typescript"]
  frameworks = ["react"]
  practices = ["testing", "git-commits"]

  [tools]
  targets = ["claude", "gemini"]        # any of: claude gemini copilot cursor windsurf codex

  [options]
  link_mode = "symlink"                 # or "copy"
  claude_agents = false
  cursor_mdc = false
  token_budget = 6000                   # 0 disables the warning
  local_tail = "ai-config.local.md"     # path, relative to project root
  gemini_commands = false
  gemini_agents = false
  cursor_commands = false
  cursor_agents = false
  copilot_commands = false
  copilot_agents = false
  windsurf_commands = false
  ```
- **`Reporter`** (`class Reporter`) — the only side-channel for output. `.act(verb, path)`
  prints `"  {tag}{verb}: {path}"` (tag is `"would "` under `--dry-run`); `.warn(msg)` prints
  `"  ! {msg}"` to **stderr**. Every `emit_*`/placement function takes one and never prints
  directly, so `--dry-run` behavior is centralized in one class rather than scattered `if`s.

### Assembly: `build_agents_md`

Reads `rules/base.md` unconditionally, then for `(kind, key)` in
`(("languages","languages"), ("frameworks","frameworks"), ("practices","practices"))`,
reads `rules/{kind}/{name}.md` for each `name` in `stack[key]` via `read_fragment` — which
**warns and returns `None`** (never raises) for a missing fragment, so one bad manifest entry
degrades gracefully rather than aborting the whole run. If `[options].local_tail` (default
`ai-config.local.md`) exists at the project root, its content is appended under a
`## Project-specific` heading. Everything is joined with a fixed `BANNER` warning not to
hand-edit the result. **Order is fixed and tested**: base → languages → frameworks →
practices → local tail.

### `check_token_budget`

`estimate_tokens(text) = len(text) // 4` — a deliberately rough English/code heuristic (an
exact tokenizer would be a dependency, foreclosed by the stdlib-only rule). Compares against
`[options].token_budget` (default `6000`; `<= 0` disables the check entirely). **Warns, never
fails** — this is a visibility tool, not a gate.

### Two placement primitives, chosen by `link_mode`

`wire_tools` defines a local `place(target, dest)` closure once, and every per-tool branch
calls it — this is *why* the branch-level code below never has to know which mode is active:

- **`rel_symlink(target, link, rep, force)`** — symlink mode. Computes a **relative** path
  via `os.path.relpath` (not absolute — survives the repo being cloned elsewhere). Idempotent:
  if the link already resolves to the same relative target, reports `"ok (symlink current)"`
  and touches nothing. A non-symlink file already at the destination is left alone (warn) unless
  `--force`.
- **`place_file`/`place_tree`** (copy mode) — real copy via `shutil.copy2`/`shutil.copytree`.
  A destination is only overwritten if it is unmanaged-and-`--force`, or already carries this
  tool's own marker: `_ours_file()` checks for the `AUTO-GENERATED by ai-sync` banner (files),
  `place_tree` writes a `.ai-managed` sentinel file into every directory it creates (so a
  re-run can tell "we made this" without banner-scanning a whole tree). `COPY_IGNORE` excludes
  `__pycache__`, `*.pyc`, `.DS_Store` — without it a stale `__pycache__` under `skills/`
  (which ships `.py` files) would land in every consuming project.

### `wire_tools` — per-target branches

One `if "<target>" in targets:` block per tool, each self-contained:

| Target | Rules entrypoint | Skills | Commands | Agents |
|---|---|---|---|---|
| `claude` | `CLAUDE.md` → `AGENTS.md` | `.claude/skills` | `.claude/commands` (symlink) | `.claude/agents`, gated on `claude_agents` |
| `gemini` | `GEMINI.md` → `AGENTS.md` | `.agents/skills` | `emit_gemini_commands`, gated on `gemini_commands` | `emit_gemini_agents`, gated on `gemini_agents` |
| `copilot` | `.github/copilot-instructions.md` → `AGENTS.md` | `.github/skills` | `emit_copilot_prompts`, gated on `copilot_commands` | `emit_copilot_agents`, gated on `copilot_agents` |
| `cursor` | none (reads root `AGENTS.md` natively) | `.cursor/skills` (unconditional) | `emit_cursor_commands`, gated on `cursor_commands`; `.cursor/rules/*.mdc` via `emit_cursor_mdc`, gated on `cursor_mdc` | `emit_cursor_agents`, gated on `cursor_agents` |
| `windsurf` | none (reads root `AGENTS.md` natively) | not wired (§ below) | `emit_windsurf_workflows`, gated on `windsurf_commands` | not built |
| `codex` | none (reads root `AGENTS.md` natively) | `.codex/skills` (unconditional — needs `CODEX_HOME` set in the project's environment; `ai-sync` cannot set it) | not built | not built |

Skills wiring is **unconditional** on the target being present at all — it is whole-directory
placement of unchanged content, the same category as the rules entrypoint, not an opt-in
transform. Commands/agents ports are opt-in booleans because each is a real text/format
transform (`emit_*`), not a symlink of unchanged content, and confidence in the target
format varies (see `docs/DESIGN.md` §11 for the sourcing behind each).

### The `emit_*` transforms

Each reads Claude-shaped source (`commands/claude/*.md` or `agents/claude/*.md`) and writes a
target-shaped file. Shared parsing helpers: `_parse_fields`/`parse_command_file` (frontmatter
+ body split for commands — frontmatter is `description:` only) and `parse_agent_file`
(frontmatter + body for agents — always exactly `name`, `description`, `tools`, `model`, in
that order). `_yaml_single_quote`/`_toml_string` escape values for the target format's own
quoting rules; `adapt_arguments_for_cursor` rewrites `$ARGUMENTS` into Cursor's fallback
phrasing (no confirmed native mechanism).

**Argument-placeholder mapping**, where one is confirmed:

| Port | Placeholder | Confidence |
|---|---|---|
| `emit_gemini_commands` | `{{args}}` | primary docs, fetched directly |
| `emit_copilot_prompts` | `${input:arguments}` | real examples, fetched directly |
| `emit_cursor_commands` | fallback phrase (`adapt_arguments_for_cursor`) | none confirmed |
| `emit_windsurf_workflows` | fallback phrase | one real example only |

**Agent tool-grant mapping**, where one is confirmed — `GEMINI_TOOL_MAP` and
`COPILOT_TOOL_MAP` translate `Read`/`Grep`/`Glob`/`Bash`/`Edit`/`Write` into that platform's
own tool names; Cursor has no per-tool allowlist at all, only a coarse `readonly` boolean
(`readonly: true` when the source agent has no `Bash`), so `emit_cursor_agents` adds an
explicit disclaimer paragraph (`CURSOR_NO_BASH_DISCLAIMER`) on any agent whose Claude grant
relies on withheld `Bash` for its "cannot execute code" guarantee — the guarantee the format
itself cannot express.

**MCP-tool guard (`_has_mcp_tools`, `MCP_PORT_SKIP_REASON`).** None of the three tool maps
recognize Claude Code's `mcp__<server>__<tool>` naming — Gemini's own docs name a different
convention (`mcp_<server>_<tool>`, single underscores) and Cursor/Copilot's MCP addressing
isn't confirmed at all. Rather than silently drop an unmapped tool (which would port
`tracker`/`docs-sync` with their Jira/Confluence capability missing while their `description`
still claims it), each of the three agent-port functions checks `_has_mcp_tools(tools)` right
after parsing and skips that agent entirely, emitting `rep.warn(...)` naming which agent and
why. See `tests/test_ai_sync.py`'s `test_mcp_tool_bearing_role_is_skipped_not_defanged` in
each of `TestCursorAgentsPort`/`TestGeminiAgentsPort`/`TestCopilotAgentsPort` for the
regression coverage, and `docs/DESIGN.md` §12 for how this was caught.

### What's deliberately NOT built, and why (so it isn't re-attempted blindly)

- **Windsurf skill wiring** — two sources disagreed (auto-discovery from `.windsurf/skills/`
  vs. manual concatenation into `.windsurfrules`) and neither was resolved against a real
  example either direction.
- **Windsurf agent port** — no real `.windsurf/agents/*.md` example found, plus the
  mid-2026 "Devin Desktop" rebrand introduced a second, differently-shaped convention
  (`.devin/skills/`) whose precedence wasn't confirmed.
- **Codex commands/agents port** — Codex's command-equivalent (custom prompts) is reportedly
  deprecated in favor of skills; no custom-agent convention was found for Codex at all.

### `apply_local_only` — the `.git/info/exclude` writer

Runs once, at the end of `main()`, only when `local_only` is true. Reads its input from
`rep.written` — `Reporter.act()`'s own log of every path it was ever called with, so this
adds no separate bookkeeping at any `place()`/`rel_symlink()`/`write_file()` call site.

- Keeps only each path's **top-level component** relative to `project_root`
  (`.claude/skills` → `.claude`) — one line covers everything under a tool's directory.
- **Never `.resolve()`s** the paths first. They are already absolute
  (`project_root / "..."`), and in symlink mode several of them *are* symlinks whose targets
  legitimately live outside `project_root` — resolving would follow the link and report the
  submodule's own path instead. A real regression this repo hit once; see DESIGN.md §14.
- Always adds `ai-config.toml` and the manifest's `local_tail` file (default
  `ai-config.local.md`) when present, alongside whatever `rep.written` produced — the
  manifest itself is this project's input, and "never committed" has to cover it too.
- Finds `.git/info/exclude` via `_git_exclude_path`, which follows a worktree/submodule
  `.git`-file's `gitdir:` redirect rather than assuming `.git` is always a directory.
- Rewrites its own marked block (`GIT_EXCLUDE_BEGIN`/`GIT_EXCLUDE_END`) rather than
  appending — the same splice-and-replace shape `gen_tree.py` uses for generated tree
  blocks — so a shrinking `[tools].targets` shrinks the excluded set too, and a byte-identical
  re-run changes nothing on disk.
- Not inside a git checkout at all → `rep.warn(...)` naming every path to add by hand,
  never a hard failure — `ai-sync`'s own sync already succeeded regardless.
- `--dry-run` reports every entry it *would* add via the same `rep.act()` path and writes
  nothing, matching every other dry-run branch in this module.

## 2. Rule fragments (`rules/`)

Plain Markdown, no frontmatter. Convention (checked by `tests/test_conventions.py`'s
`TestLangGlobs`, informally elsewhere): starts with `## <Title>`, stays tight — commands,
constraints, conventions, not architecture-overview prose (that inflates every session's
context for no benefit). One concern per fragment. `rules/base.md` is always included;
everything else is opt-in via `[stack]`. A language fragment needs a matching entry in
`bin/ai-sync`'s `LANG_GLOBS` dict (only consumed by `emit_cursor_mdc`, when `cursor_mdc =
true`) — `TestLangGlobs` fails in both directions: a fragment with no glob, or a glob with no
fragment.

## 3. Skills (`skills/<name>/SKILL.md`)

Frontmatter is **exactly** `name` (kebab-case) and `description` — checked by
`test_conventions.py`'s `TestSkills`. The description should be "pushy": specific enough that
an assistant's own routing picks it for the right prompts (`test_descriptions_are_specific_enough_to_trigger`
does a light heuristic check). Scripts/templates live alongside `SKILL.md` in the same
folder. `skills/role_review/SKILL.md` is the one skill every reviewing agent loads — see §4.

## 4. Commands (`commands/claude/*.md`)

Frontmatter is **`description:` only** — no `argument-hint`, no `allowed-tools`. Body is
bolded, numbered, imperative steps; the file ends with a trailing bare `$ARGUMENTS` line.
Checked by `test_conventions.py`'s `TestCommands`. Two commands carry the layer's hardest
invariant: `role.md` and `role-review.md` must never invoke `developer` directly
(`test_developer_is_never_invoked_by_the_review_commands`) — only `role-implement.md` may,
and only after it has itself completed backlog-existence, non-empty-item-list, staleness, and
clean-worktree checks (see its own body for the exact order — skipping step 2, the empty-item
refusal, is called out explicitly as never-skippable).

Current inventory: `review`, `test`, `role`, `role-review`, `role-backlog`,
`role-implement`, `sync-tracker`, `sync-docs` — see `docs/INVENTORY.md` for one-line purposes.

## 5. Agents (`agents/claude/*.md`)

Frontmatter is **exactly** `name`, `description`, `tools`, `model`, in that order (parsed by
`test_conventions.py:parse_frontmatter`, a ~15-line hand-rolled splitter — no PyYAML, keeping
the stdlib-only rule). `name` must equal the filename stem. `model` is a bare alias
(`opus`/`sonnet`) — never a pinned model ID, so agents survive model version bumps. `tools`
is a comma-separated list that always ends in `Skill`. `description` must contain an explicit
`Do NOT use…` clause — that clause is what auto-delegation keys off, not a nice-to-have.

Body shape (reviewing roles): H1 role name → 2–3 sentence second-person identity paragraph →
the line "Load the `role-review` skill first for the output schema, severity scale, and
context budget…" → `## Context strategy` → `## What to look for` → `## Steps` → `## Rules`.
No contractions, em dashes throughout, hard numeric caps stated as literals — matching
`role_review/SKILL.md`'s own register.

### The tool-grant matrix (the actual trust-boundary enforcement)

`test_conventions.py`'s `EXPECTED_AGENTS` is this table verbatim — a mismatch fails CI:

| Agent | Model | Tools | Finding prefix |
|---|---|---|---|
| `qa` | sonnet | Read, Grep, Glob, Bash, Skill | `QA` |
| `architect` | opus | Read, Grep, Glob, Bash, Skill | `ARC` |
| `product` | sonnet | Read, Grep, Glob, Bash, Skill | `PRD` |
| `engineering-manager` | sonnet | Read, Grep, Glob, Bash, Skill | `EM` |
| `sre` | sonnet | Read, Grep, Glob, Bash, Skill (Bash fenced to git-metadata-only by body rule) | `SRE` |
| `senior-dev` | opus | Read, Grep, Glob, Bash, Skill | `SDR` |
| `ciso` | opus | Read, Grep, Glob, Skill — **no Bash** | `SEC` |
| `planner` | opus | Read, Grep, Glob, Skill — **no Bash** | n/a (aggregator, not a reviewer) |
| `developer` | opus | Read, Grep, Glob, Bash, **Edit, Write**, Skill | n/a (implements, doesn't review) |
| `tracker` | sonnet | Read, Grep, Glob, `mcp__atlassian__{searchJiraIssuesUsingJql,getJiraIssue,createJiraIssue,editJiraIssue,transitionJiraIssue,addCommentToJiraIssue}`, Skill — **no Bash** | n/a |
| `docs-sync` | sonnet | Read, Grep, Glob, Bash, **Edit, Write**, `mcp__atlassian__{getConfluencePage,createConfluencePage,updateConfluencePage,searchConfluenceUsingCql}`, Skill | n/a |

Derived invariants `test_conventions.py` checks directly: `Edit`/`Write`/`NotebookEdit`
appear **only** on `developer` and `docs-sync`
(`test_only_developer_and_docs_sync_can_modify_a_repo`); `ciso` and `planner` hold **no**
`Bash` at all (`test_ciso_and_planner_have_no_shell_at_all` — `tracker` also holds none, by
the table above, though it's grouped with the MCP-only roles rather than this specific test);
every agent's tool list ends in `Skill`; every reviewer (`REVIEWER_PREFIXES`, the 7 roles
above with a finding prefix) has its `role-review` skill-load line in its body and owns a
unique, documented finding-ID prefix.

`adapters/claude-agent-permissions.json` is the piece a `tools:` grant cannot express by
itself: `Bash(true)` on a role does not mean "any command" is intended, only that some Bash
is needed (git metadata, running a test suite). Its `permissions.deny` rules narrow that —
merged by hand into a project's `.claude/settings.json` (never auto-written, since that file
is the project's own). These rules are **project-wide**, not per-agent — Claude Code has no
per-subagent permission scoping — so they also constrain the human's own session, a tradeoff
stated plainly in `README.md` rather than hidden.

## 6. `skills/role_review/run_manifest.py` — the run ledger

Stdlib-only script, invoked from the *target* repo's context (`--project <path>`), writing
`.ai-reviews/manifest.json`:

```json
{"schema": 1, "runs": [
  {"sha": "<short-sha>", "started_at": "<iso8601>", "dirty": false,
   "roles": {"qa": "qa.md"}, "backlog": "BACKLOG.md", "audit_score": 72}
]}
```

Functions: `git()`/`head_sha()`/`is_dirty()` shell out to `git` read-only; `load_manifest`/
`save_manifest` are the JSON round-trip; `latest_run` returns the most recent run entry;
`archive_run(reviews, sha)` moves every `*.md` and `audit_data.json` at the top level of
`.ai-reviews/` into `archive/<sha>/`, leaving `manifest.json` itself untouched (it outlives
the runs it describes).

Three CLI verbs, composed by the commands in §4:

- **`--begin [--sha <sha>]`** — if the latest run's sha differs from the current one,
  archives it first, then opens (or reuses, if the sha matches — same-commit re-runs stay
  idempotent) a run entry for the current sha.
- **`--record <role>=<relpath>` [repeatable]**, **`--backlog <file>`**, **`--audit-score
  <int>`** — note a persisted artifact against the currently-open run. A malformed
  `ROLE=FILE` pair warns and is ignored rather than aborting the whole recording.
- **`--status`** — prints HEAD's sha vs. the manifest's latest recorded sha and exits
  `0` (current), `1` (stale — reports predate HEAD), or `2` (nothing recorded yet). This exit
  code is exactly what `role-implement.md` step 3 branches on to refuse acting on a backlog
  pinned to an older commit.

## 7. `skills/repo_tree/gen_tree.py` — the annotated tree

Implements HLD §8's documentation layer. Stdlib only, like every other script here, and
standalone: `run_audit.py` invokes it as a **subprocess by path**, never an import, so the
two skills stay independently copyable (same rule as `ProjectOverrides.load` in §6's
neighbourhood — see DESIGN.md §4).

- **`collect_paths(root)`** — `git ls-files -z` via `subprocess`, falling back to an
  `os.walk` pruned by `PRUNE_DIRS` when the target isn't a git checkout. Tracked files only:
  a new file joins the map at `git add`, which is what makes the CI gate exact.
- **`Annotator.note_for(rel, is_dir)`** — the note precedence, and the precedence is the
  contract: `docs/.structure-notes.toml` override → frontmatter `description:` → first
  markdown heading → Python module docstring (also for extensionless files with a Python
  shebang, which is how `bin/ai-sync` gets a line) → a directory's own `README.md` heading.
  A human's override always outranks a heuristic. `_trim(shorten=False)` for overrides:
  derived notes get clause-level shortening, hand-written ones only the length cap.
- **`render_tree` / `TreeRenderer`** — folds paths into nested dicts, draws box connectors,
  honours `--max-depth` and collapses directories past `--max-entries` into `… N more`.
- **`splice(text, block, params)`** — rewrites only between
  `BEGIN GENERATED TREE`/`END GENERATED TREE` HTML comments, and **stamps the parameters into
  the BEGIN marker**. That stamp is what lets `--check` rebuild any marked file at the depth
  it was originally made, without being told. A missing marker is an error (exit 2), never a
  silent whole-file overwrite.
- **`marked_files(root)`** — requires a *complete, ordered* BEGIN/END pair. A doc that
  merely describes the convention in prose (DESIGN.md §13 does) must not be mistaken for a
  block to rewrite; a lone BEGIN previously aborted the entire check run.
- **`run_check(root)`** — regenerates every marked file, prints a unified diff, exits `1` if
  any is stale, `0` otherwise. `DocumentationAnalyzer._structure_doc_is_stale` in
  `run_audit.py` branches on exactly those codes, and maps anything else to `None` —
  "couldn't check" is deliberately distinct from "current".

## 8. `tests/` — what's actually checked, and by what

- **`test_ai_sync.py`** — subprocess-drives `bin/ai-sync` against a synthetic submodule/project
  fixture built by `SyncHarness` (real files with marker content, e.g. `BASE-MARKER`,
  `PY-MARKER`, plus fixture agents `demo` (no Bash), `demo-writer` (Bash+Edit+Write), and
  `demo-mcp` (an `mcp__atlassian__createJiraIssue` tool, for the MCP-skip regression tests) —
  never against this repo's real content, so fragment/agent additions here can't accidentally
  break the generator tests. Covers assembly order, idempotency, `--dry-run`, `--force`,
  `claude_agents` gating, `link_mode` both ways, the token-budget warning, and every `emit_*`
  port including the MCP-skip guard.
- **`test_conventions.py`** — parses this repo's *real* `agents/claude/*.md`,
  `skills/*/SKILL.md`, `commands/claude/*.md`, `skills/role_review/SKILL.md`, so it is the
  live enforcement of everything in §5 above; a role added without updating the enumerations
  in `role-review/SKILL.md`, `role-review.md`, or `role.md` fails here.
- **`test_run_manifest.py`** — drives `run_manifest.py` against a real temporary git repo
  (actual commits, actual `git rev-parse`), covering begin/record/status, archive-on-new-commit,
  idempotent re-begin at the same sha, and the three `--status` exit codes.
- **`test_structure_doc.py`** — two jobs. `TestRepoIsCurrent` is the drift gate: it runs
  `gen_tree.py --check` against **this** repo, so adding or renaming a tracked file without
  regenerating fails CI. The rest drive the generator against throwaway git repos, pinning
  the note precedence, that prose outside the markers survives, that a missing marker errors
  instead of overwriting, and that `--check` rebuilds from the stamped parameters.

Run before and after touching anything under `bin/`, `agents/`, `commands/`, or `skills/`:

```bash
python -m unittest discover -s tests -v
```
